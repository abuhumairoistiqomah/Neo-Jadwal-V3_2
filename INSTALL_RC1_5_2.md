# Install — E-JADWAL V3.20 RC1.5.2

Start from **RC1.5.1**. The postponed sorting feature is NOT included.

1. Back up Supabase and source. Use a staging database first.
2. Apply `supabase/migrations/202610230006_v3_20_rc1_5_2_faithful_incidental_copy.sql`.
3. Run `supabase/verifiers/202610230006_v3_20_rc1_5_2_readonly.sql`.
4. Extract patch into the RC1.5.1 project root. It must not overwrite `.env.local`.
5. Run `npm.cmd run lint`, `npm.cmd run test:320`, and `npm.cmd run build`.
6. Test a new copy from `12 AE 1` JP4–JP5 to a target, including a combined-class note. Check Dashboard, Jadwal Kelas, Daftar Insidental; verify reason/type/special note equal source while class identity and room remain target-owned. Click Edit, adjust one teacher and save.
7. Existing RC1.5/RC1.5.1 copies with **unchanged autogenerated markers** and valid audit provenance have their visible reason/type and combined metadata corrected during migration; teacher teams are NOT automatically overwritten. If teachers are still wrong, use the existing **Perbarui hasil salin** option to re-copy from source, then adjust teachers individually.

## Precautions

- A copied combined-class flag and its description don't create an independent enrollment/attendance-transfer record. Cross-class operations must still be explicitly configured.
- The room is intentionally target-owned. Avoid silently cloning source rooms across separate classes. Set a shared room explicitly in the dated editor when physically combined.
- All copy writes remain one transaction, administered only by an authorized ADMIN/WAKASEK. No master changes.
- The migration performs a **bounded** normalization of pristine legacy copy labels; save the SQL preview/backup first. The audit action `NORMALIZE_LEGACY_COPY_METADATA_RC152` records the correction.
- Full Vite build and live PostgreSQL execution must be verified in your own staging environment.
